# Arthur — Style Selection Procedure

## When to load

When an incoming task asks to choose, revise, or justify the visual language of a website, landing page, or web application. Read `visual-styles.md` for stylistic vocabulary and limitations.

## Decision flow

1. Read the task and approved requirements; treat them as hard constraints.
2. Check whether visual direction already exists. If yes, reuse it without unsolicited style changes.
3. Identify missing facts that materially change the choice. Ask narrowly; never invent them.
4. If selection is actually required, shortlist at most 2–3 materially distinct options compatible with the requirements.
5. Compare UX benefit, clarity, information density, brand compatibility, accessibility, implementation cost, maintainability, and risks. Use only known facts. Don't pretend subjective taste is measured evidence.
6. Reject any option that violates a hard constraint, even if it has numerous minor advantages.
7. Recommend the solution only if its *important* benefits substantially outweigh the alternative's benefits and its own drawbacks.
8. If no clear winner exists, state the trade-off and request approval. Do not select arbitrarily.
9. Label speculative preferences explicitly as hypotheses and seek approval before establishing a new dominant style.
10. After approval, document actionable parameters for typography, grid, colors, components, media and responsive behavior. Specify exact values when approved or technically required; do not invent brand tokens.

## Required output when proposing a visual style

- **Task:** what is requested, without expanding scope.
- **Known inputs:** concrete requirements and approved constraints.
- **Open questions:** only decision-critical missing information.
- **Options:** genuine alternatives, each with meaningful pros and cons.
- **Recommendation:** only when one option clearly dominates on material criteria.
- **Hypotheses:** marked clearly and not presented as approved.
- **Approval request:** only for significant unconfirmed design decisions.
- **Handoff:** precise styling and interaction specifications only after approval, as appropriate to the request.

## Prohibited shortcuts

- Choosing a style because it's current, impressive, or the model prefers it.
- Treating brand or audience assumptions as facts.
- Using a glass/glow/3D/animation effect solely to embellish.
- Presenting a long list of fake options with no material differences.
- Counting trivial benefits to beat one serious UX drawback.
- Changing product strategy or conducting final visual QA.
